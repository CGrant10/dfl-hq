# Live Book settlement — 1.414.0

The Book now refreshes the selected member's tickets, bankroll and receipts together without reloading the page. An open bet slip keeps its stake, focus and quoted picks; its available balance updates. A settled ticket remains in its current list position for this visit. Historical results are quiet, and observed wins produce one payout moment per refresh rather than one per ticket. Paid tickets display the actual payout.

The new `sportsbook_my_live_account()` RPC is a read-only, stable, security-invoker SQL wrapper around the existing selected-member read APIs. Tickets (30), receipts (16) and balance share one database snapshot. It grants execution to the same public API roles, uses an empty search path and adds no direct table privileges. Polling never creates wallets, claims allowances, settles tickets or changes bets. Existing initial wallet setup and explicit actions are preserved. The selected-member/PIN access model is unchanged.

Verified in the deployed database: no member returns null; selected-member IDs and balances match the existing APIs; the wrapper is stable, invoker and has no PUBLIC execution grant. Supabase security and performance advisors did not report the new function. Existing project advisory findings are outside this change.

GameDay gives one prominent moment to each shared model update: a verified lead change first, otherwise the highest visible newly crossed player milestone or the largest score surge. Other players retain score deltas and hot/cold effects. Unknown baselines, stat corrections and historical results do not manufacture celebrations. Motion off, reduced motion and hidden-page cleanup remain supported.

Validation covers settlement deduplication, reload and member isolation, simultaneous results, storage failure, incomplete or wrong-member snapshots, independent account/quote failures, pauses during writes, and accounts with no mounted markets. Browser checks use isolated read fixtures with all business writes intercepted, at 320, 390 and 430 pixels in Chromium and WebKit. They exercise an open slip during settlement, accepted ticket odds, retained ticket nodes and focused Share controls, reading position, selected tabs, disclosures, receipts, failure retention and GameDay effect cleanup. Browser emulation does not verify physical iPhone keyboards or haptics.

# Mobile launch and live continuity — 1.413.0

App boot previously required the commissioner sync engine, notification implementation, member-preview UI and breaking coverage before identity restoration could start. Sync now imports its existing pipeline only after the commissioner invokes it and passes the permission/config checks. The three background UI features and notification nudge import after the first route is ready. Identity restoration, PIN gates, release coherence and the updater retain their existing order. A source dependency walk reduces the required app entry graph from 101 modules to 61, deferring 362,594 source bytes. Home and other routes may still need some of those modules themselves; this is a dependency reduction, not a guaranteed device startup percentage.

Home's three-post preview and the full Wall refresh while the document is visible and catch up after reconnect/resume. Updates retain the composer, attachment, open conversations, reply draft and cursor. New posts preserve the visible reading anchor. Open conversations fetch new replies without recreating their form and keep a focused composer in place as replies arrive. Active edits, submissions and open dialogs delay background refresh. Existing content remains on read failure. A successful post resets only its own composer. Reaction listeners abort their prior registration before rebinding; reply and draft controls initialize once.

Sportsbook refresh reads only mounted market/outcome IDs through its existing batched loader, then patches prices, labels, line values and lock states in place. Tab/filter controls and selected picks remain mounted. An open slip delays refresh, so its stake and review quote do not change underneath the user. Lines that close outside the slip are disabled and removed from its selected package; submit-time database checks and accepted ticket prices are unchanged. Background refresh neither touches wallets nor places/grades tickets. New markets and ticket settlement still arrive through the existing full-book reload. Action-triggered reloads keep the prior book visible during the read and reject late results after navigation.

Live-score/recovery timers stop on pagehide, including late request completion, and coalesce a forced read on a persisted pageshow. Draggable sheets release pointer capture and clear an interrupted pull when the page suspends. Native dialog bounds recalculate on window resize and pageshow as well as VisualViewport resize/scroll; close removes those listeners.

Validation uses the real app, guarded league reads and isolated synthetic quote/reply fixtures at 320, 390 and 430 px. It checks retained DOM/focus/selection, attachments, post insertion/deletion, active edits, composer reset, moving quotes, slip stability, closed lines, new replies, duplicate handlers, phone viewport bounds, route cleanup and the opaque More cover. Browser writes are intercepted. Screenshots, cloned auth state and raw checks remain outside the repository in `/workspace/dfl-continuity-1413/`.

WebKit checks run in Linux phone emulation. They do not establish physical iOS installation, native keyboard behavior or OS push delivery. Unit checks, production builds, PR/main workflows, deployed asset parity and live browser checks must complete before release verification is finished.

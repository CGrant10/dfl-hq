# League checks and larger trades — v1.369.0

Trade searches now default to eight total players, including reset and team-switch paths. Older stored drafts upgrade their previous four-player ceiling once; newly selected smaller ceilings remain saved. Adding required players expands the ceiling automatically, up to eight total across all participating teams. The legacy playerIds search input retains every required player instead of silently keeping only two. Bounded package sampling and existing value, usefulness, availability and one-QB restrictions remain in place. A search can still return no qualified offers; it never relabels an unfavorable deal to fill a tier.

Before sharing a proposed trade, the page bypasses its shared model cache and reads current Sleeper rosters, player availability and weekly injury data. Missing providers, duplicate ownership and stale injury fallbacks block sharing. Ownership changes reconcile the draft; injury, reserve, material value or rating changes update the ticket and require a second review. A concurrent edit or route exit cannot share the old package. Latest team names and explicit split recipients flow through the existing share-card renderer. Completed historical receipts are unaffected.

Protected background sync and lineup workers validate all 12 roster IDs and owners, player ownership, starting players, weekly matchup coverage, active season/week and the DFL PPR starting format before writing score/roster data or sending alerts. Reserve membership repeated in the players list is valid; zero placeholders are not real starters. Failed validation preserves previous league snapshots. Sync stores a counts-only report with fixed issue codes in sleeper_config.last_league_health. The existing commissioner Performance panel displays the report and flags an overdue snapshot. Provider errors remain visible through sync status.

Lineup alerts group new problems into one notification per owner in the existing 90-minute kickoff window. The earliest affected kickoff bounds expiry. A SHA-256 source key deduplicates concurrent identical groups; notification_messages.lineup_alert_keys remembers each notified player/severity, including existing individual source keys. Later polls and shrinking groups stay quiet. Questionable→Out can send one escalation; a downgrade does not repeat an already reported Out problem. Push length stays within the sender's existing 240-character limit; fuller details remain in Team Analyzer. Recipient targeting and phone opt-in rules are unchanged.

The additive league_health_schema.sql migration extends the existing commissioner-gated summary and adds the two metadata columns. Deploy sync-sleeper with its health/context dependencies, lineup-alerts with health/context and lineup dependencies, then send-notification. All workers retain their existing custom cron-token authentication. Dry-run calls validate real provider data without writing snapshots or sending messages.

Validation covers complete/malformed league snapshots, reserve duplication, five required players, default 4-for-4 discovery, legacy draft upgrades, stale injury rejection, fresh ownership/injury reads, multi-party recipient preservation, notification grouping, poll deduplication and severity escalation. Mobile browser checks exercise real trade handlers and existing card flows. Reverting frontend/worker sources retains historical snapshots, notification history and share cards; the additive metadata columns can remain.
